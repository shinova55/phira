Protocol-v2 testing prerelease with the private-chart transfer improvements from PR #3, contributed by @RadiatedExodus.

**Upgrade every player’s client and the multiplayer server together.** The previous `v0.8.2-private-mp.1` packages use protocol v1 and are incompatible. Login/authentication is unchanged.

## Improvements

- Stream chart uploads and downloads over the existing multiplayer connection, using 256 KiB chunks and a 2 MiB flow-control window.
- Check chart metadata and validate cached files before downloading. Valid cache hits skip the archive transfer, and the host reuses its uploaded snapshot.
- Keep control traffic responsive during transfers and bound transfer buffers and inactivity waits.
- Keep transferred charts under `mp-local/<SHA-256>`, outside the visible Local library. There is still no Save to Local feature.
- Include all required Windows fonts and pause the Windows launcher on errors so startup failures remain visible.

**User-tested result, October 17, 2026:** PR #3’s Android/Windows test builds worked, with chart loading reduced from roughly **30 seconds to 2–4 seconds** in that setup. This is an observed result, not a guaranteed loading time. Network conditions, chart size, server load and cache state affect performance.

Keep each client’s executable beside its complete `assets` folder. Linux requires system libraries and a desktop/OpenGL environment for the game; see the [Linux setup notes](https://github.com/shinova55/phira-custom-mp/blob/v0.8.2-private-mp.2/docs/linux-test-build.md). The server package is for hosting only. Restart your server with this version and configure all clients to use its address.

**Android:** the optimized APK is signed with a new ephemeral test key and retains the official package ID. It cannot update the official app or previous test builds signed with another key. Back up/export data before reinstalling, or use a separate Android user/profile. No signing secrets are required or included. Windows is unsigned.

## Verification and limitations

Publication requires Android, Windows and Linux builds, repository checks, Windows client tests, multiplayer workspace tests, package checks, Linux game startup under a virtual display, and a server listening-port check. Uploaded release assets are downloaded back and SHA-256 verified before publication. One controlled latency benchmark is intentionally ignored by normal test runs; it is not a failed test.

The PR test builds were user-tested; these newly packaged release binaries have not separately undergone a full real-device multiplayer test. Linux gameplay/crossplay, real audio/performance, all devices and every disconnect/rejoin scenario remain unverified.

- **Official score uploads remain unavailable, including catalogue scores.** These public-source builds lack the closed official record/attestation implementation. Use the official client for official scores/RKS. Private scores are room-only and trust-based.
- Archives are limited to 32 MiB compressed, 128 MiB extracted and 4096 ZIP entries, with SHA-256 verification. Server archives remain in room memory while the room exists.
- Cache validation and room readiness still take time. Repacking a chart can change its archive hash. Cached files can remain on disk; there is no bounded eviction policy or visible Local library registration.
- Source archives include the modified server but exclude closed official code and signing keys. Builds download external dependencies and upstream assets; Android also uses the upstream APK shell.
